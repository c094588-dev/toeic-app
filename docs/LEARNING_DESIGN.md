# 学習設計（間隔反復と今日の学習）

作成日: 2026-10-25。実装は `mobile/src/learning.ts`、テストは `mobile/tests/learning.test.mjs`。

## 結論

- 改善前は「覚えた」1 回で習得扱い、復習は一律 7 日後、1 日の復習枠は 5 語だった。覚えた語が 35 語を超えた時点で復習が追いつかなくなり、玩具モデルの推定では 180 日後に「覚えた」1,000 語超に対し復習待ち 1,000 語・保持率 4 割になる。
- 1.1 では **固定ラダー式の間隔反復（Leitner 系）＋遅延ボーナス＋新規上限＋おさらいモード** に置き換えた。2 ボタン（覚えた／まだ）のまま、設定なし、ユーザーに説明できる。同じモデルで 180 日後の保持率は 9 割超（推定）。
- FSRS／SM-2 は却下。1,500 語・1 日 20 語の規模では精度差より堅牢さが効く。

## 単語ごとの記録（`WordStat`）

```ts
{ miss: number; seen: number; step?: number; due?: number }
```

- `miss`: 苦手度（まだ・誤答で +1、クイズ正解で −1、覚えたで 0）。
- `seen`: 最後に答えた時刻。
- `step`: 段階 0〜8。`due`: 次に出す時刻（その日の 0 時に揃える）。
- 保存形式は `toeic.progress.v1` の **version 2 のまま**項目を足した（旧アプリでも読める）。`step/due` のない記録は読み込み時に補う。

## 間隔の表

```
step:      0   1   2   3    4    5    6     7     8
次の復習:  当日 1日 3日 7日 14日 30日 60日 120日 240日
```

- 定着 = step 5 以上（次の復習まで 30 日以上）。設定画面の「うち定着 n 語」。
- 既知語 = 答えを見ずに「覚えた」→ step 3（7 日後）から。上級者が 500 点の語に毎日つき合わされないため。

## 更新規則

| 出来事 | 更新 |
| --- | --- |
| 覚えた（初めて、答えを見てから） | step 1（翌日） |
| 覚えた（初めて、答えを見ずに） | step 3（7 日後） |
| 覚えた（復習の時期が来ていた） | 経過日数に見合う段まで一気に上げて +1（遅延ボーナス: 60 日放置して思い出せたなら 60 日段の次） |
| 覚えた（時期の前、レベル別の自主練など） | step／due は据え置き（同じ日に何度見ても間隔が延びすぎない） |
| まだ | 苦手度 +1。step は 2 つ下げる（全部は戻さない。一度覚えた語の記憶は残っている）。すぐ出す |
| 答えを見ただけ（判定なし） | `seen` だけ更新（今日の学習数に数え、同じ日にもう一度出さない）。覚えた単語には何もしない |
| クイズ正解 | 時期が来ていれば +1（遅延ボーナスなし。認識課題は想起より軽い）。記録がなければ step 1 |
| クイズ誤答 | 「まだ」と同じ |
| 耳だけ復習で聞いた | 記録しない（受動的な露出は想起ではない）。「まだ」を押したときだけ「まだ」 |

## 今日の学習（`todayPlan`）

```
size      = 20（残りがあればその分。目標達成後は 10）
対象      = 目標スコア以下のレベル（マイ単語帳を含む）、今日まだ答えていない語
1. 復習   = 時期が来た語を step 昇順 → due 昇順（不安定な記憶から）。最大 size − min(4, 新しい単語の枠)
2. 新しい = マイ単語帳 → 低いレベルの順に、1 日 10 語まで（既知語は枠を使わない）
3. 前倒し = 足りなければ 2 日以内に時期が来る語
おさらい  = 復習待ちが 60 語を超える、または最後の学習から 7 日以上 → 新しい単語は 0
さらに10語 = 目標達成後に自分で選んだときだけ、新しい単語の上限を超えてよい
```

- 今日の目標は 20 語。出せる語が少ない日はその数が目標になり、その日のあいだ固定する。
- 結果画面の「明日は 復習 n 語・新しい単語 m 語」は、同じ関数を翌日の時刻で呼んで出す。

## 既存データの移行（1 語も失わない）

| 既存の状態 | 導出 |
| --- | --- |
| 覚えた・記録あり（v2） | step 3、due = seen + 7 日 |
| 覚えた・記録なし（v1） | step 3、seen = 7 日前、due = いま |
| まだ・記録あり | step 1、due = seen + 1 日 |
| まだ・記録なし（v1） | 苦手度 1、step 1、due = いま |
| 更新で一度に時期が来た「覚えた」語 | 14 日に分けて出す（番号 % 14 日後）。更新直後に復習だけの日が何日も続かないように |
| 未来の時刻の記録 | 「いま」に丸める |

## 出題形式の使い分け

| 形式 | 性質 | 使いどころ |
| --- | --- | --- |
| 英 → 日（カード） | 受容的想起。最も速い | 今日の学習の既定 |
| 日 → 英（カード） | 産出的想起。難しいが両方向を伸ばす | 設定で切替（保存される）。答えを出すまで発音しない |
| 4 択 | 認識。1 問 6 秒。客観 | 「確かめる」。苦手と時期の来た語を優先。語義の重なる語（customer／client）は誤選択肢にしない |
| 耳だけ復習 | 音 → 意味。手が使えない場面 | 単語 → 1.8 秒 → 意味 → 例文。記録がある語を優先して 20 語 |

## 根拠（主な研究）

- 分散効果・間隔: Cepeda ら 2006（メタ分析）、Ebbinghaus 1885（Murre & Dros 2015 が再現）
- テスト効果・想起練習: Roediger & Karpicke 2006、Karpicke & Roediger 2008、Karpicke & Blunt 2011
- 産出的学習: Webb 2009
- 意味の近い語の干渉: Nakata & Suzuki 2019
- Leitner 1972（箱方式）、FSRS: Ye ら 2022（規模に対して過剰と判断）

## 却下した案

FSRS 本体の導入、4〜6 段階の自己評価ボタン、学習時間・連続日数を主指標にすること、「さらに」で新しい単語を無制限に出すこと（既定では上限を守る）、期限切れの語を自動で「まだ」に落とすこと、LLM による例文の動的生成。
